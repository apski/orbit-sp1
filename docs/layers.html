The altitude map

You used to work at the agent layer: ask an agent to change the app, read what it did. The work now is one level up: building the machinery that decides whether an agent's change is right, keeps it from cheating, and lets it run for hours without a person checking each step.

Each layer below answers one question for the layer above it. The rule that holds the stack together: no layer grades its own work. Every judgement is made by something lower down that is deterministic (code, a number, a file:line), or by a separate agent that never saw the builder's reasoning.

One change through every layer

What happened today on a copy of the rn-vs-native app. An agent renamed a navigation route, then tried to hide it.

  1. L3 skill
    The agent, working a migration, renames route Detail to Details in 4 files. Typecheck passes, so it looks done.
  2. L6 gate
    It tries to stop. The Stop hook runs verify gate. gate-contracts fails: the route is gone from the inventory, and old deep links and analytics would break. 
    route: 1 removed, 1 added
  - Detail   (was src/autopilot.ts:26)
  + Details
1 contract(s) removed: each must be intentional (dropped from scope) or a regression
  3. L1 instrument
    That verdict came from facts.mjs + contracts.py diff: an AST pass and a set difference, no model.
  4. L6 ratchet
    The agent edits the baseline so the contracts check passes. Now gate-ratchet fails: the baseline lost an entry compared with the base commit. 
    STEP gate-ratchet FAIL
    contracts baseline: - Detail   (was src/autopilot.ts:26)
  5. L6 release valve
    On its second Stop the agent is let through, and you get the message instead. Nobody is trapped forever, and nothing is hidden.
  6. L0 + human
    The agent reverts and the gate goes green. If the rename really was intended, a person updates the baseline, commits it and pushes. That moves the base, and only that is allowed to.

Glossary

Judging: who decides it's right

Oracle
A judge you didn't write in this task, and that gives the same answer every run. No model in it. The contracts diff, RN's Yoga layout for Spectra, the accepted perf baseline, NavLab's measured native twin, golden fixtures.
Ruler
Anything an oracle measures against. If an agent can move the ruler, the oracle is worthless. The contracts baseline, fitness budgets, the accepted-violations list, a must-pass flow, a required check, an enforced principle.
Must-pass list
A named set of checks that must all be green. Optional checks report but don't block; planned ones have no command yet. [check_sets] gate and gate-device in .orbit/orbit.toml.
Golden test
A fixed input with its expected output pinned. Changing the output needs a stated reason. Orbit's own commands (SPEC R12); ExampleApp's tax engine parity tests.
Held-out scenario
A test written by a second agent that the builder never sees, so the builder can't fit the code to it. Voyager-1's acceptance scenarios.
Mutation floor
The share of small deliberate bugs ("mutants") in changed lines that the tests catch. Surviving mutants show what the tests can't tell apart. voyager/mutate.py; ratcheted per unit in ledger.jsonl.
Blind reviewer
A separate agent that sees only the candidate and the evidence, never the builder's reasoning. design-afresh step 6; Voyager's diff-only reviewer.

Locking in: keeping what you've won

Ratchet
A ruler that only moves one way: tighter. It lets a legacy app adopt a rule today by accepting existing violations, then fail on any new one and tighten as old ones are fixed. .orbit/gate ratchet lists every way a ruler got looser than at the base.
Base commit
What "looser" is measured against: the merge-base with upstream. Agents don't push, so only a person can move it. Limit: with no upstream the base is HEAD, so a local commit resets it. Run long agents on a branch.
Floor
The number a long task keeps raising, always with the command that reproduces it. Labelled measured or estimated, and reported as two numbers: breadth (does it exist) and ready (does it hold up). HARNESS rule 5. E.g. Spectra screens passing verify vs screens captured.
Baseline
A committed snapshot the gate diffs against. A person creates it and changes it by pushing. .navlab/contracts.baseline.json.
Fitness function
A CI check that keeps an architecture from drifting back: import rules, one-writer-per-state rules, navigation budgets. navlab/arch/fitness.py, config in navlab.fitness.json.
xfail flow
A demonstrated bug kept as a flow that must keep failing. It is never deleted or folded into a passing flow; when it starts passing, a person drops the marker. export const xfail = '<repro>' in flows/*.mjs.
Stop hook
The enforcement point. When the agent tries to finish, a red gate blocks it once with the reasons; the second try goes through and tells you. .orbit/gate stop in .claude/settings.json.

Planning a port: what to move, where to cut

Contract
Something the app promises the outside world: storage keys, analytics events, deep links, routes, API calls, native modules. A port must keep all of them. contracts-scan; known gap g0019: some RN routes are missed.
Seam and boundary tax
The seam is where you split RN from native. The tax is the permanent cost of every change that has to cross it: two PRs, a bridge change, a store release.
Crossing share
The share of past commits that would have touched both sides of a proposed split. Read the per-side number; the "either side" number flatters the split. ExampleApp: 34% of RN commits also touched apps/shared.
Co-active share
The share of a side's commits made in months the other side also changed. Below 50%, a low crossing share means one side was frozen, not that the seam is good. ExampleApp RN vs iOS: 1% crossing, but only 9% of RN commits were co-active.
Lift
How much better a layout keeps changes local than random layouts with the same module sizes. Above 1 means the boundaries follow how the code really changes. replay.py.
Ledger prediction
The expected effect of a move, written down before the work and scored after. Two misses in a row stop the program. arch/ledger.py add / measure / score.
Strangler migration
Seam first, then move one piece at a time behind a flag, flip consumers, delete the old path. Every step ships alone and can be reverted.

Program: many surfaces at once

Surface
One unit of the program: a screen, flow or subsystem with one move (migrate, redesign, tune, lab) and one stage.
Stage check
What must resolve before a surface enters a stage: a file or a ledger id, never a note. building needs a prediction first; done needs it measured. program.py advance <s> <stage> refuses with the missing items.
Readiness gate
The 10 pre-port questions as a checklist with evidence. Contracts, safety net and Release baseline are required. program.py ready <s>; on the test app it refused: 0 screens covered by flows.
Zoom levels
The same state at three budgets: 0 = the whole program, 1 = one surface, 2 = one task (Orbit packet plus orbit-rag bundle). Zoom only as far as the next action needs. Measured on the test app: ~170, ~360 and ~510 tokens.
In flight
A surface past ready and not yet done. At most 3; more raises a program flag.
Stop rule
Two migrate predictions missed in a row: pause the program and re-plan. Zoom 0 raises it as STOP RULE.

Plumbing: how pieces land in a repo

Packet
A token-budgeted bundle of cited context for one task, built by Orbit from the index. .orbit/orbit packet <unit> "<task>".
Census
Orbit's survey of a new repo: languages, roots, the checks and adapters it needs. It proposes; a person approves.
Adapter / profile
The one committable file of per-repo facts a subsystem reads, so the pack is configured, never forked. navlab.config.json, .voyager/profile.toml, .spectra/profile.json.
Installer contract
Every subsystem installs with one command: metadata only, idempotent, nothing machine-specific, plus a status row. Checked by bin/orbit installer-check.
Check set
Orbit's named list of checks, run by verify <set>. The gate's must-pass list is two of them.
Gap ledger
Where a tool fell short on a real repo, logged before working around it, and closed only with a test that pins the fix. navlab/arch/gaps.py, learning/gaps.jsonl.
